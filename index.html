L1

Hello Triangle

最小繪圖流程：三個頂點、RGB 逐像素內插。

VBO/VAOshader內插
重點筆記
  • VBO：存放頂點資料的 GPU 記憶體。
  • VAO：說明書，告訴 GPU 怎麼讀那堆數字。
  • Shader：跑在 GPU 的小程式；vertex 定位置、fragment 定顏色。
  • 三個角的顏色被 GPU 逐像素內插，形成漸層。
🧠 隨堂小測

Vertex shader 和 Fragment shader，哪個跑的次數多？

看答案

Fragment shader。Vertex 每個「頂點」跑一次（三角形才 3 個），Fragment 每個「像素」跑一次（可能上萬個）。

L2

Colors + Uniform

用 uniform 每幀傳時間，讓三角形旋轉、明暗呼吸。

uniformuTimesin 呼吸
重點筆記
  • 頂點屬性：每個頂點各自不同（例如顏色）。
  • uniform：這一幀所有像素相同，由 CPU 每幀傳入（如 uTime）。
  • out→in 搭配逐像素內插，是之後光照／貼圖的基礎。
🧠 隨堂小測

顏色是「頂點屬性」還是「uniform」？兩者差在哪？

看答案

顏色是頂點屬性（每個頂點各自不同）。uniform 這一幀所有像素相同、由 CPU 每幀傳入（例如 uTime）。

L3

矩陣變換

用矩陣旋轉一個彩色正方形，取代手寫三角函數。

mat4rotate
重點筆記
  • 一個 mat4 能同時表達平移／旋轉／縮放，還能相乘疊加。
  • shader 裡永遠只要 uModel * vec4(pos,1.0) 一行。
  • 相乘順序不可交換：GLM 裡越右邊的矩陣越先作用到頂點。
🧠 隨堂小測

在 GLM 裡，T * R 和 R * T 畫出來有什麼不同？

看答案

最右邊先作用。T*R＝先旋轉再平移＝在該位置「自轉」；R*T＝先平移再旋轉＝繞原點「公轉」。

L4

MVP 立方體

拖曳

Model·View·Projection + 深度測試，第一個真正的 3D。

MVP深度測試透視
重點筆記
  • MVP：Model(到世界) → View(到相機) → Projection(到螢幕)。
  • 透視投影用長寬比修正，正方形才不會被壓扁。
  • 深度測試：開啟後近的面才會擋住遠的面。
🧠 隨堂小測

gl_Position = P * V * M * pos，這三個矩陣各把頂點從哪帶到哪？

看答案

M：物體→世界；V：世界→相機視角；P：相機→螢幕（透視＋長寬比）。最右的 M 先作用。

L5

相機

拖曳環繞

拖曳讓相機繞著一堆方塊飛 —— 每幀重算 View 矩陣。

lookAt環繞
重點筆記
  • 相機 = 位置 + 朝向 + 上 三個向量。
  • 每幀重算 lookAt(pos, pos+front, up)。
  • 移動量乘 deltaTime，速度才不受幀率影響。
  • 左右移動 = cross(front, up)（外積求右方向）。
🧠 隨堂小測

為什麼移動距離要乘上 deltaTime？

看答案

讓速度與幀率無關——不管電腦跑幾 FPS，每秒移動的距離都一樣。

TEX

貼圖

拖曳

把圖片貼上表面：UV 座標 + 取樣器。

UVsampler2D
重點筆記
  • UV 座標(0~1) 告訴 GPU 頂點對應圖上哪個位置。
  • wrap：超出範圍怎麼包（REPEAT 平鋪）。
  • filter：LINEAR 平滑、NEAREST 馬賽克。

🧠 隨堂小測

貼圖座標 (0,0) 和 (1,1) 分別對應圖片的哪個角？

看答案

(0,0)＝左下角、(1,1)＝右上角。GPU 逐像素內插 UV，把圖貼滿整個面。

LIT

Phong 光照

拖曳

環境光 + 漫反射 + 高光，物體變立體，光源繞圈。

法線diffusespecular
重點筆記
  • Phong = 環境光 + 漫反射 + 高光 三層相加。
  • 漫反射靠 dot(法線, 光方向)：越正對越亮。
  • 高光靠 reflect：反射剛好進眼睛時最亮，會隨相機移動。
  • 法線描述每個面朝哪，是光照的核心。
🧠 隨堂小測

漫反射用哪個數學運算決定一個面有多亮？為什麼？

看答案

dot(法線, 光方向)（內積）。面越正對光源、夾角越小，內積越大＝越亮；背對＝0＝暗。

MAP

光照貼圖

拖曳

Specular map 決定哪裡反光：亮點只落在橘格子上。

diffuse mapspecular map
重點筆記
  • diffuse map：表面本來的顏色。
  • specular map：黑白圖，決定哪裡會反光。
  • 一張 specular map 就能讓同一物體有多種材質（木頭 + 金屬邊）。
🧠 隨堂小測

specular map 是什麼樣的圖？它控制什麼？

看答案

一張黑白（灰階）圖。白＝該處會反光、黑＝不反光。讓同一物體不同部位有不同材質。

CAST

多光源 · 衰減

拖曳

點光源繞圈，靠近的方塊亮、遠的暗 —— 距離衰減。

point lightattenuation
重點筆記
  • 方向光(太陽)：無位置、統一方向、不隨距離衰減。
  • 點光源(路燈)：有位置，用 attenuation 越遠越暗。
  • 聚光燈(手電筒)：只照一個圓錐，接上相機就是手電筒。
🧠 隨堂小測

點光源和方向光最大的差別是什麼？

看答案

點光源有「位置」且隨距離衰減（越遠越暗）；方向光沒有位置、不衰減、方向到處一樣（像太陽）。

SHADOW

陰影

拖曳

物體在地板上投下陰影，太陽緩緩繞圈。

FBOshadow mapPCF
重點筆記
  • 兩次渲染：先從光的視角記錄深度成「深度圖」。
  • 正常畫時比對「像素深度 vs 深度圖」→ 更遠 = 在陰影。
  • FBO：畫到貼圖而非螢幕（後處理特效也靠它）。
  • bias 防表面雜紋、PCF 柔化陰影邊緣。

🧠 隨堂小測

shadow mapping 為什麼需要「渲染兩次」？

看答案

Pass1 從光的視角把場景深度畫成「深度圖」；Pass2 正常畫時比對深度，判斷像素有沒有被別的東西擋住（在陰影）。

Unproject — 白話解說

Project（投影）＝拍照：3D 世界的點經過 MVP 壓成 2D 螢幕位置。Unproject＝倒著走：拿螢幕上的點（例如滑鼠位置）反推回 3D。

關鍵難點：螢幕上一個點，其實對應 3D 世界裡一整條射線（那條線上所有點拍出來都落在同一像素）。所以只靠 2D 座標只能得到「一條射線」；要唯一定位一點，還需要深度（多遠）。

做法：把 MVP 反過來乘（用 inverse(Projection)、inverse(View)），把螢幕座標倒推回世界。

記法：Project＝拍照 3D→2D；Unproject＝看照片反推 2D→3D，只能得到射線，除非知道深度。用途：滑鼠點選、射線、深度圖轉點雲。

02Shader Programming

名詞簡單理解實際應用

HLSL／GLSL撰寫 Shader 的語言Unity、Unreal、OpenGL、DirectX

你做過的 Phong Lighting 是進入 PBR 前的重要基礎：Ambient、Diffuse、Specular、Normal、Light Direction 都會繼續出現在後續材質學習中。

PBR — 白話解說

Phong 像化妝：手動調 ambient/diffuse/specular「調到看起來對」，換個燈光就可能露餡。PBR 是真材實料：照真實世界光怎麼反彈來算，材質（例如黃金）不管在什麼光線下都對——這個「一致性」是最大價值。

不再調沒意義的數字，改用看得懂的旋鈕：Albedo（本色）、Metallic（是不是金屬 0~1）、Roughness（多粗糙）。

兩個物理原則：能量守恆（反射不能比照到的多）＋微表面（表面是幾百萬面小鏡子；越粗糙→反光越散越模糊）。

對照 Phong：你的 pow(...,32) 反光集中度 → Roughness；手調的 specular 顏色/強度 → Metallic + Albedo。記法：Phong＝化妝；PBR＝真材實料。

BRDF — 白話解說

材質的「反光食譜」：給它「光來的方向 + 我看的方向 + 材質」，它回你「這點該多亮」。名字裡的 Bidirectional（雙向）就是指同時看這兩個方向。

你 Phong 裡的 diffuse + specular 就是一個簡化版 BRDF——你早就在做，只是不知道名字。PBR 用更精確的 Cook-Torrance 版本。

它的高光 = D × F × G：D＝多少小鏡子朝對方向（由 roughness 決定）、F＝Fresnel（掠射角反光更強，像遠看桌面/水面會反光）、G＝小鏡子互相遮擋。公式不用背。

記法：BRDF＝材質的反光食譜（光向+視向→亮度）。你的 Phong 是簡化版；PBR 版＝D(粗糙)×F(掠射反光)×G(互遮)。

IBL — 白話解說

用「環境的照片」（360° 全景/天空盒/HDRI）整片當光源。真實物體不是被幾顆燈照，而是被四周所有東西（天空、牆、地面反彈）照亮——IBL 就在還原這件事。

兩個重點：① 物體會融入場景，像真的待在那；② 金屬非它不可——金屬的特色是反射周遭，沒有 IBL 金屬球會黑黑死死（沒東西可反射）。所以 PBR 和 IBL 常綁在一起。

記法：幾顆燈＝黑房間裡的手電筒；IBL＝直接在戶外/亮房間，光從整片天空四周來。它是你 Phong 那個平平的 ambient 的高級版。

你已經碰過 Depth Buffer，這正是 Frame Buffer 與後續 G-Buffer 的入口。你的練習也驗證過：沒有深度測試時，後方表面可能錯誤蓋住前方表面。

Forward Rendering — 白話解說

你現在的渲染器就是這種：每畫一個物體，就當場把所有燈算完、直接輸出像素。

優點：簡單，透明物件、VR 都好處理。缺點：燈一多就爆（算光次數 ≈ 物體數 × 燈數），而且可能對「最後被別的東西擋住、根本看不到」的表面也白算了光。

記法：Forward＝每個物體當場算光。簡單，但燈多會累、還會浪費在看不到的表面。

Deferred Rendering — 白話解說

核心一句：「先記筆記，最後再一次算光」。分兩階段：① 先不算光，只在每個像素記下「什麼顏色、面朝哪、離多遠」；② 收集完再統一把光算完。

為什麼這樣比較好：(A) 便利貼只留最前面看得到的，所以只算看得到的像素、不浪費（不像 Forward 可能白算被柱子擋住的牆）；(B) 算光次數 ≈ 螢幕像素 × 燈數，和物體數脫鉤，超多光源也不怕。

缺點：透明物件難處理、G-Buffer 吃記憶體。

記法：Forward＝每個物體當場算；Deferred＝先記筆記再統一算（燈多也快，但耗記憶體、不好處理透明）。

Render Target — 白話解說

「畫出來的東西送去哪」。預設是螢幕；但也可以把畫面送進一張貼圖。

你陰影課做過：把場景深度畫進一張深度貼圖，那張貼圖就是一個 render target。

記法：Render Target＝繪圖的目的地。螢幕是預設的，貼圖也可以當一個（你陰影的深度圖就是）。

Frame Buffer — 白話解說

管理「一次渲染要輸出到哪些附件」（Color 顏色、Depth 深度…）的容器。把東西畫進 FBO 而不是螢幕，就叫離屏渲染 (off-screen)。

你陰影課用的 FBO 就是 framebuffer——後處理、反射、G-Buffer 全都建在它上面。

記法：Frame Buffer (FBO)＝畫面輸出的容器；畫進它＝離屏渲染。是所有進階特效的入口。

Render Pass — 白話解說

一段「有明確輸入與輸出」的渲染工作。一個畫面通常由好幾個 pass 疊出來（Shadow pass、不透明物件 pass、透明物件 pass、後處理 pass…）。

你陰影課的「兩次渲染」＝ depth pass（從光的視角）+ main pass（正常畫）＝ 兩個 render pass。

記法：Render Pass＝一段獨立的渲染工作。你陰影的兩次渲染就是兩個 pass。

G-Buffer — 白話解說

Deferred 第一階段記下的那「一疊便利貼」的真面目：一組貼圖，每張只存一種資料——顏色、法線、位置/深度、材質(roughness/metallic)。

破解名詞：Buffer＝一塊 GPU 記憶體（VBO 是裝頂點的 buffer，貼圖是裝像素的 buffer），沒很玄。印出來看：法線那張是怪彩虹圖、深度那張是灰階圖、顏色那張像沒打光的場景。

記法：G-Buffer＝把場景資料拆成好幾張貼圖先存著（顏色/法線/位置/材質），之後算光查表用。

MRT — 白話解說

Multiple Render Targets：一個 shader 一次就寫進好幾張貼圖（不用把場景重畫好幾遍、一遍產一張）。

對照你會的：陰影課的 FBO 只掛 1 張深度圖；MRT 就是同一個 FBO 掛好幾張，shader 一次把它們全寫好——這正是拿來一次生出整組 G-Buffer 的技術。

記法：MRT＝一次畫進好幾張貼圖。你陰影做過「畫進 1 張貼圖」，MRT 就是變成「一次好幾張」。

HDR — 白話解說

一般顏色每通道是 0~1（1＝螢幕能顯示的最亮）。但真實世界太陽比白牆亮幾千倍，全砍到 1 就失真（太陽和白牆一樣亮）。

HDR＝允許顏色超過 1（白牆=1、檯燈=5、太陽=1000），先把真實的亮度範圍保留下來給計算用（之後 Bloom、曝光才分得出誰真的亮）。

記法：HDR＝讓亮度能超過 1，保留真實範圍。你現在的 0~1 叫 LDR。

Tone Mapping — 白話解說

螢幕只能顯示 0~1，那亮到 1000 的 HDR 畫面怎麼顯示？Tone Mapping＝把超大的 HDR 範圍漂亮地壓縮回 0~1。

就是相機的曝光、或你眼睛的適應：從暗房走到大太陽下，眼睛自動調整，讓亮的暗的都看得到細節。不同壓縮曲線＝不同風格（電影感、膠片感）。

記法：Tone Mapping＝最後把 HDR 壓回螢幕的 0~1，像相機曝光／眼睛適應。

Bloom — 白話解說

讓超亮的地方向外發光（霓虹燈、太陽那種光暈）。三步驟：① 抽出很亮的部分（亮度>1）→ ② 把它模糊（光向外擴散）→ ③ 疊回原畫面。

為什麼跟 HDR 綁一起：第 ① 步要挑「很亮」的地方，若顏色被砍在 0~1 就分不出誰真的亮；有 HDR 才知道太陽該發光、白牆不用。第 ②③ 步的抹糊/疊回都用 FBO（畫進貼圖再處理）。

記法：Bloom＝抽亮部→模糊→疊回，做出光暈。需要 HDR 分辨亮度、用 FBO 做模糊。

Motion Vector — 白話解說

記錄每個像素「從上一幀移到這一幀，移了多少」的小箭頭。疊前後影格前，先用它「追」到像素在上一幀的正確位置。

用途：TAA（避免會動的東西疊出殘影）、Motion Blur（動態模糊）、DLSS（AI 放大畫面）。

記法：Motion Vector＝每個像素的移動箭頭，讓疊圖能對準會動的東西。

TAA — 白話解說

Temporal Anti-Aliasing（時間性抗鋸齒）。每幀讓相機極輕微抖一下（方向每幀不同），再把連續好幾幀疊起來平均→ 鋸齒被抹平。便宜又有效，現代遊戲幾乎都用。

和你做過的 PCF 精神一樣：多取樣、平均→變平滑。PCF 是空間上取周圍，TAA 是時間上取前幾幀。會動的東西靠 Motion Vector 對準，才不會殘影。

記法：TAA＝把好幾張「微抖」的影格疊起來平均，抹掉鋸齒（時間版的 PCF）。

04GPU Programming

核心心智模型：GPU＝幾千個簡單的工人，同時做同一件事（CPU 則是幾個聰明工人、一件一件做）。這階段全在講「怎麼組織這些工人」。你的 fragment shader「每個像素跑一次」，那幾百萬次就是這幾千個工人平行跑的。

GPU Pipeline — 白話解說

就是你熟的生產線：頂點 → 光柵化 → 像素，GPU 幫你排好的固定流程。這階段一部分是看懂它、找瓶頸（例如 Draw Call 太多會拖慢）。

記法：GPU Pipeline＝GPU 內建的繪圖生產線；懂它才能找效能瓶頸。

GPU Memory (VRAM) — 白話解說

GPU 自己的記憶體，放 Mesh、貼圖、Buffer。你的 VBO/EBO/貼圖全都住在 VRAM 裡。資產最佳化＝別讓它爆（4K 貼圖很吃 VRAM）。

記法：VRAM＝GPU 的記憶體，你的頂點/貼圖都住這。

Compute Shader — 白話解說

前面的 shader 都綁死在「畫三角形」（vertex 管頂點、fragment 管像素）。Compute Shader 掙脫這條線：讓你用 GPU 那幾千個工人跑自己的程式、處理任何資料，不一定要畫圖。

用途：粒子系統、影像處理、物理模擬、資料生成 / AI 運算。

記法：GPU＝幾千個工人同時做同一件事；Compute Shader＝把工人從「只能畫三角形」解放出來，拿去算任何東西。

Thread Group — 白話解說

把幾千個工人分成小隊。同一隊可共用一塊快取「小白板」（shared memory）、互相傳紙條合作；跨隊不行。（compute 裡自己設一隊多大。）

記法：Thread＝一個工人；Thread Group＝小隊，隊內共用小白板合作、比各自去大記憶體拿快。

Warp / Wave — 白話解說

GPU 不是一個一個調度工人，而是一排 32 個綁在一起、同一口令一起動（NVIDIA=Warp、AMD=Wave）。

後果：if/else 會變慢——一排 32 人若有些走 if、有些走 else，硬體只好「先全做 if（該走 else 的乾等）→ 再全做 else」，一排被拆開效率砍半（＝分支效能問題）。

記法：Warp/Wave＝32 個 thread 一排、動作一致；把一排用 if/else 拆開就變慢。

Occupancy — 白話解說

GPU 同時維持多少「有在幹活」的工人 vs 它的上限。高＝工人都有事做、就算有人在等記憶體別人可先做（有效率）；低＝一堆工人閒著乾等（浪費）。

記法：Occupancy＝工人有沒有被餵飽。高＝GPU 忙而有效率、能藏記憶體延遲。

GPU Instancing — 白話解說

畫一萬棵草若「一棵一個指令」→ CPU 要喊一萬次、忙成瓶頸。Instancing＝一個指令說「這 mesh 畫一萬次，位置在這」，GPU 自己重複。

你做過「一份幾何＋迴圈畫很多方塊」是它的精神，但那是迴圈喊很多次；真正的 instancing 是一次指令畫全部（glDrawArraysInstanced）。用途：草、樹、群眾、粒子。

記法：Instancing＝一個 draw call 畫大量相同 mesh，省掉 CPU 的重複指令。

Mesh Shader — 白話解說

傳統幾何前段（vertex shader 那條）較死板。Mesh Shader＝更彈性的現代做法，讓 GPU 更自由地產生／裁切幾何，能先剔除看不到的三角形不浪費力氣（GPU-driven rendering）。較新硬體才有。

記法：Mesh Shader＝幾何管線前段的彈性升級版，GPU 自主產生/裁切幾何。

Async Compute — 白話解說

平常 GPU 的繪圖工作和 compute 工作是輪流做。Async Compute＝讓 compute 和繪圖「同時」進行，趁繪圖單元有空檔塞 compute 進去 → GPU 不閒置、利用率更高。

記法：Async Compute＝繪圖與運算並行，填 GPU 空檔、提高利用率。
